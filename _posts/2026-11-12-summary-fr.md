### [Faille RCE critique CVE-2026-119618 dans le module mod\_http2 d&\#x27;Apache HTTP Server](https://www.wiz.io/blog/cve-2026-119618-rce-apache-http-server-vulnerability) ⭐️ 8.0/10

Selon le titre et l&\#x27;analyse fournis, Wiz publie un billet signalant une vulnérabilité critique d&\#x27;exécution de code à distance, identifiée CVE-2026-119618, dans le module mod\_http2 d&\#x27;Apache HTTP Server. Le contenu détaillé du billet n&\#x27;était pas disponible, de sorte que les versions touchées, les conditions d&\#x27;exploitation et l&\#x27;étendue de l&\#x27;exposition ne peuvent pas être confirmées ici. Un commentaire renvoie vers un commit de correctif dans le dépôt officiel d&\#x27;Apache, mais ce lien n&\#x27;a pas été vérifié.

hackernews · soheilpro · Nov 12, 02:11 · [Discussion](https://news.ycombinator.com/item?id=50462177)

**「Contexte」** Le module mod\_http2 est le composant d&\#x27;Apache HTTP Server qui gère le protocole HTTP/2, une version plus récente du protocole web qui permet de multiplexer plusieurs requêtes sur une même connexion. Un article de The Hacker News relève que la faille touche des serveurs sur lesquels HTTP/2 est activé, et CISA a publié un avis la concernant. Selon le même avis, le problème vient de défauts de sécurité des threads \(thread-safety\), ce qui signifie que des accès concurrents mal synchronisés peuvent être exploités.

**「Action pour les administrateurs」** Les administrateurs qui exécutent Apache HTTP Server avec le module mod\_http2 doivent appliquer le correctif sans tarder, car la faille CVE-2026-119618 \(synchronisation défaillante dans assign\_headers\(\)\) peut mener à une exécution de code à distance. Un outil de détection tiers indique que d&\#x27;autres CVE, comme CVE-2026-106023, ont leurs propres plages de versions touchées, donc un lot ne peut pas être déclaré sain au seul motif que cette CVE n&\#x27;est pas concernée.

**「Discussion communautaire」** Un commentateur affirme que cette faille serait la première classée « critique » par Apache depuis 2021, affirmation qui n&\#x27;a pas été vérifiée. Un autre rappelle qu&\#x27;arrêter Apache avec systemctl ne suffit pas toujours si une tâche cron ou un timer systemd de certbot peut le redémarrer.
